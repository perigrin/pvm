# Fixing PSC's parser: what it would take

Date: 2026-09-04
Status: investigation only — nothing changed

## The problem

89 of 227 `t/op` files have parse errors (39%, 756 error nodes). Every
type diagnostic is computed on whatever survived parsing, so both coverage
and mutation detection are bounded by this rather than by the checker.

## Where the parser lives

    PSC  →  gotreesitter v0.51.0  →  grammar_blobs/perl.bin  (a BINARY blob)
                                  +  grammars/perl_scanner.go (hand-written)

The blob is generated by `cmd/ts2go` from an upstream tree-sitter grammar,
pinned in `grammars/languages.lock`:

    perl  https://github.com/tree-sitter-perl/tree-sitter-perl
          0c24d001dd1921e418fb933d208a7bd7dd3f923a  src  .pl,.pm

**That SHA is not in upstream's `master` history.** `git cat-file` cannot
find it in 217 fetched commits. It is from the `release` branch, which
carries generated artifacts — so the pin tracks a build output rather than
a grammar revision, and there is no obvious way to tell how old it is from
the lock file alone.

## The three parser bugs are ALREADY FIXED UPSTREAM

Checked against a fresh clone of tree-sitter-perl (currently 1.2.1):

| bug | upstream |
|---|---|
| `format NAME = ... .` unrecognised | `format_statement` at grammar.js:319, with `format_content` read by the external scanner |
| `/x` lexed as the binary `x` operator | `match_regexp_modifiers: /[msixpodualn]+/` at grammar.js:1468 |
| heredoc bodies parsed as live code | 23 heredoc rules in the grammar |

Confirmed locally that PSC gets them wrong today: `/a/x` produces
`ERROR "x"` as an orphaned node after the regex closes at `/`.

## Options, cheapest first

### 1. Bump the grammar pin and regenerate (LIKELY SUFFICIENT)

This is the same shape as the fix earlier today, where upgrading
gotreesitter 0.6.0 → 0.51.0 took inference coverage from 0.1% to 38%
because quoted strings finally parsed. The toolchain is present in
`~/dev/gotreesitter`: `cmd/grammar_updater` refreshes the lock,
`cmd/ts2go` regenerates.

Cost: unknown but bounded. Risk: a newer grammar changes node kinds, and
PSC matches on those by name in ~40 places. The last upgrade broke guard
narrowing exactly this way (`ambiguous_function_call_expression`), and the
tests caught it.

Not attempted here — it means regenerating a dependency and re-pinning
PSC's `go.mod`, which is a change to make deliberately rather than at the
end of a session.

### 2. Ask upstream gotreesitter to bump

The pin lives in gotreesitter, not PVM. If the blob is stale for
everyone, the fix belongs there and benefits every consumer. PSC would
then just move to the next release.

### 3. Suppress diagnostics inside ERROR subtrees (MITIGATION, not a fix)

Cheap and dishonest in isolation: it hides the symptom while coverage
stays where it is. Worth doing ONLY alongside 1 or 2, so that a file which
fails to parse reports "not analysed" instead of a list of confident
diagnostics about text the parser misread — the `header_parser.t` case
where a 496-line heredoc body yielded 495 diagnostics.

### 4. Hand-patch `perl_scanner.go`

The scanner is hand-written Go and already handles quote state, heredocs
and paired delimiters. Editing it is possible but it is a vendored file in
the module cache, so the change would have to live upstream anyway — which
is option 2 with more steps.

## Recommendation

Option 1, then 3. The upstream grammar already fixes all three bugs, so
this is a version-pin problem rather than a parsing-theory problem. The
measurement to repeat afterwards is the parse-error rate over `t/op`: 89
of 227 files today.

The paren-less-call and `my %h = 1..20` bugs from the triage were NOT
confirmed as upstream-fixed and may be genuine grammar limitations or
PSC-side issues; they need separate investigation.

## ATTEMPTED 2026-09-04: regenerate the blob. Reverted.

### What was tried

1. `go list -m -u` — **v0.51.0 IS the newest release.** There is no version
   to bump to; the stale grammar is baked into the current release.
2. Upstream gotreesitter `main` (2c19a78c) pins perl to `ad74e6db`, which
   is OLDER than the release branch and has `format_statement` count = 0.
   Pinning a pseudo-version would not have fixed anything.
3. `format_statement` was added in tree-sitter-perl `d1c2417`
   ("Grammar fixes + corpus coverage from real-world triage #254"), and
   master is at `c3e17b3` (1.2.1).
4. Regenerated from master: `tree-sitter generate` (28MB parser.c), then
   `go run ./cmd/ts2go` → 5749 states, 585 symbols vs 488 today.

### The result was decisive in both directions

**The grammar fix works.** With the regenerated blob:

    t/op: 227 files, 0 with parse errors (0%), 0 error nodes

down from **89 files, 756 error nodes**. `/a/x`, `format NAME = ... .`
and heredocs all parse with zero errors.

**But the blob is broken.** 149 tests fail across `internal/{infer,parser,psc}`,
and not because of renamed node kinds — the root node comes back as
`srand`:

    "!1;"             -> (srand)
    "push @a, 1;"     -> (srand (function))
    "my $x = 42;"     -> (source_file (expression_statement ...))   correct

The symbol table is MISALIGNED: symbol IDs in the generated blob do not
match the names the runtime resolves. Simple statements parse correctly
and anything reaching a different symbol range does not. That is a
ts2go/runtime version mismatch, not a PSC problem and not something to
paper over.

Everything was reverted: `~/dev/gotreesitter` restored, `go.mod`
unmodified, `third_party/` removed, `make test` green.

### What this establishes

The parse-error problem is REAL and FIXABLE — 39% to 0% is not a marginal
gain — but the generation toolchain in the pinned gotreesitter cannot
currently produce a working blob from the current upstream grammar. The
fix has to happen in gotreesitter, either by its maintainer regenerating
with a matched ts2go, or by finding which ts2go revision produces an
aligned symbol table for the 1.2.x grammar.

Vendoring was the chosen approach and is not viable until that is
resolved: a vendored blob that misparses is worse than a stale one that
parses a subset correctly.

### Reproduction, for whoever picks this up

    cd /tmp/.../tsp && git checkout master && tree-sitter generate
    cd ~/dev/gotreesitter && go run ./cmd/ts2go \
        -input .../tsp/src/parser.c -output /tmp/perl_new.go -name perl
    # writes grammar_blobs/perl.bin alongside the .go file
    # swap it in, then: my $x = 42  parses; !1  comes back as (srand)
