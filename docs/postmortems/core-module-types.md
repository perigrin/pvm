# Milestone core-module-types Postmortem

## What Worked Well

- **Perl as the judge, end to end.** 54 issues done; `git zhi verify --timeout 900 core-module-types` 413/413 at d4786743. Every library is held to perl 5.42 for prototypes, exports, returns and (from 01a15aaa) parameters, with WRONG = 0 and TestInferencePrecision at 65/76 throughout. The lib baseline never took a false positive: two attempts to add one (6ccc's `qualify`, the sockets widening) were refused at merge.
- **The signature audit.** Five fresh auditors found ~210 defects (A POSIX 102, B 20, C 33, D 35, E 20) that all four existing hold tests passed. The parameter oracle (01a15aaa) now holds that class mechanically.
- **Opus with a per-fix review (round 4 on).** Every round-4 and narrow-round fix was caught at least once before merge: 46b4 three passes, 4587 three, 453e two, c491 three. 453e cut 300 nested ifs from 24s to 0.2s (pu 1.6s).
- **CI became real.** At execute, CI was green while every perl-held test skipped. 6b81, 5b21 (five follow-ups), win3 and frompvm made it require perl 5.42 on Linux, macOS and Windows, with per-name platform exemptions that fail when stale.

## What Didn't Work

- **The review did not converge.** Fix rounds in the flow-narrowing and call-check code kept introducing defects the next lens found: round 2 found 11 Important (mostly round 1's), round 3 8, round 5 3, the final lens 4 (N1–N4, 01a16499). Per-fix reviewers checked the named finding's neighbourhood; the fresh lenses wrote new adversarial probes and found what they missed.
- **Execute declared done on a vacuous gate.** Goal (7) "CI is green" held while CI ran no perl-held test; only review round 1 (I4) saw it.
- **Parameters were never held.** carp's and croak's parameter types passed every gate; perigrin found the class by asking a question.
- **Machinery failures:**
  - the disk filled (44 merged worktrees, 6,815 stale go-build dirs);
  - about 10 `pgrep -f` wait loops matched themselves and never ended;
  - qmerge left a conflicted merge in place;
  - msgate only appended, so three rounds of review minutes were silently dropped;
  - a 15s timing bound flaked under parallel load.
- **Rework rate 29.6%; 69 WIP violations** (sanbao).

## What Puzzles Us

- Why per-fix Opus reviewers, each with probe tables over 1,000+ files, still passed A1, B1 and N1–N4. The tables reused the review corpus; new defects lived outside it.
- The always-run versus maybe-zero loop trade-off oscillated across builds (pu and h3 report a7/a8/a10, r2 and h4 do not). Each fix moved the error to the mirror case.
- Two of my own semantic claims reversed after measurement: carp's parameter type, and Moose "dropping flags".

## What Will We Change

1. **Hold parameters in every new library milestone.** Refinement makes the parameter oracle (TestOracleCasesFitDeclaredParameters) an acceptance criterion beside prototypes, exports and returns.
2. **A "CI is green" condition names the tests that must run.** Use a require flag like PVM_REQUIRE_PERL542, plus a criterion that fails on a skip.
3. **Commit the regression-probe corpus.** r2probes, r3probes, r4/p, r5probes, rv491, rv6 and fl6 become a committed fixture with a perl-judged table test. Every fix in internal/infer flow or call checks runs it mechanically against pu and the previous head.
4. **Per-fix reviews must also write new adversarial probes** outside the existing corpus. That is what found every defect the per-fix reviews missed.
5. **Bound the review loop in refinement.** Default: two fix rounds, then follow-ups. Install the plugin release that carries crochet:discernment.
6. **Measure before asking.** A ruling question to perigrin quotes a perl measurement of the behaviour it describes.
7. **Tooling, done in this milestone, kept:**
   - qmerge aborts on conflict and prunes worktrees on merge;
   - the worker brief forbids `pgrep -f` waits;
   - minute writes replace rather than append;
   - timing tests bound only what load cannot mask.
