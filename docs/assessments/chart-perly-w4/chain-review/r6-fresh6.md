## Traced and found sound

- **Answer keys.** The 27 answer keys in `baseline.txt` are counted exactly by d2d1's filter. `chartInputs` computes `Accepted` only when recognition succeeded, so a precedence refusal that moves from the pipeline into the chart leaves `Accepted` unchanged. `items-per-token` and `set-reuse` are the only keys that move, and both are excluded.
- **Criteria re-run at milestone end.** No criterion asserts a transient state that a later issue undoes. This holds for d1c2's digest pins against d278's regeneration, d135's and d218's resolved-digest holds, d166's and 3262's `refused-where.txt` holds, and d199's V1-side source.
- **perl.git.** CI's Ratchets job fetches perl5 and runs `make chart-precedence-reference` with `pipefail`. The new perl.git tests fail rather than skip, so a FAIL fails the job. Every local criterion that needs perl.git is guarded by `[ -d "${PERL5_CORPUS:-…}/t" ]`.
- **Derived form against the committed tables.** `len(tab.Rules) == len(g.G1)` holds today (`buildParsePrecedence`), so the content test does not silently switch production's judgement off.
- **Refusal rerun order.** 3262's order (un-narrowed no-precedence rerun, then narrowed, then `precedence`) reproduces V1's order: grammar or lex-unmapped, then scope, then precedence. This holds for each two-fault case I built, including precedence followed by a resolve scope fault.
