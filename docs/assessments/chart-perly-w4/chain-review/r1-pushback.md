# chain-review round 1: pushback (plan quality) on chart-perly-w4

**Recommendation: modify.** Seven findings are blocking. Five come from tracing what the code does at each intermediate state, not from reading the criteria. The order of work is sound. Most criteria are red before their work, and their negative scenarios are unusually strong. The defects sit where one issue's change reaches a file that a later or parallel issue's criterion pins.

## How this was checked

- I read the chain live: `git zhi milestone show`, `git zhi issue list --milestone chart-perly-w4`, and `git zhi list`. It has 17 issues and 162 criterion lines, and every line yields one command (last paren span).
- I ran every criterion against the tree at `e3432c0f` (HEAD) with the repo's own `internal/chart/offline/criteria-lint.sh`, which runs each non-`guard:` command with `sh -c`. **161 of 162 are red today.** The one green criterion is d199's `TestRecognitionKeysUnchangedByPipeline` "passes or is retired" check. It is a legitimate regression guard, but it is not labelled `guard:` (R9). The lint found no pin on a file that a later issue edits.
- The installed git-zhi is **0.5.2**, below the 0.7.0 floor. `verify --dry-run` therefore reads only done issues, so step 2.5 is empty by version, not by content. The lint stands in for it. No AC line carries two paren spans, so the first-span and last-span rules agree.
- `go test` behaviour behind SQE #1 was checked in a scratch module. A top-level `t.Skip` prints `--- SKIP: X`, not `--- PASS`. A parent whose subtests all skip prints `--- PASS`.

Dependency DAG (A → B means A blocks B):

```
d02f, d05d, d089 ─────────────┐
d0ba → d0e1, d10d ────────────┴→ d135 → d166 → d199 → d1c2 → d1eb ──────────────┐
                                                          └→ d218 → d247, d278, d2a2 ┴→ d2d1 → bb9b
```

The graph has no cycles, and every model label is present. The critical chain is 10 issues long: d0ba→d0e1→d135→d166→d199→d1c2→d218→d247→d2d1→bb9b.
