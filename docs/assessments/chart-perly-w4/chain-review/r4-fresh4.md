## Recommendation: modify

There is one blocking finding, FR4-1. The design says an infeasible grammar's tables are refused. The chain instead pins that an infeasible grammar is recognized without judgement. Once `ParseWith` drops `Constrain`, that becomes a precedence off-switch reached through the grammar.

On the question I was asked: the run-time "tests this change moves" check is a good detector, but it is not enough. See FR4-2 and FR4-3.

- When an issue's list is incomplete, the check turns a planning gap into a design §7 stop at run time. Fixing an unlisted red test is an amendment of a started issue, and §7 makes that a stop.
- The check is blind to tests behind the `precedencereference` build tag.
- Several issues that change behaviour do not run the check at all.
