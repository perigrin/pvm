# R1 review — Chapter 2, Lexical Structure

Target: `02-lexical-structure.md`, 2511 lines. Method: the four-rung ladder
(1 need to exist? 2 said elsewhere? 3 stdlib does it? 4 shorter?) applied per
section. Every "stdlib does X" claim below was run on go1.24.4; every "perl
does X" claim was run on 5.42.0; every "duplicated in ch N" names both line
ranges.

Verdict up front: the chapter is fundamentally sound. The toke.c citations and
the `[verified]` corrections are the best material in the whole spec and none
of them should move. The problems are (a) three chapters each own "the lexer
checkpoint" and they disagree, (b) about 400 lines describe toke.c internals
the Go implementer is then told not to copy, and (c) one 125-line table that
replaces a one-line rule.

## The three things I would actually do

1. **Make ch6 §6.3.1 the only checkpoint struct and delete ch2 §2.14's
   competitor** — right now the two disagree on the state count (11 vs 2) and
   on the safe-restart condition (`XSTATE` vs `ExpectTerm`), and an
   implementer will build whichever they read first.
2. **Replace §2.7.5's 125-line variable table with the `isGRAPH_A` rule from
   `toke.c:11032`** — the table is not the rule, cannot be complete (verified
   `@;` and `%;` exist), and calls `$#` "deprecated" when the same chapter
   correctly says it is fatal.
3. **Add `strconv` to §2.8 and cut §2.8.7/2.8.9/2.8.10** — the section is
   silent on the one thing the stdlib does for free, and spends 50 lines on
   value conversion and a third copy of the divergence list instead.
