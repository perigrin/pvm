**perigrin's ruling (2026-10-23, chain-review round 7): canon is precedence-aware, and the call-paren forgiveness rule is removed.** Canon emits named unary ops, `not` and list operators by their precedence, from CORE.tpm's derived shapes and powers. It writes a call's parens only where the source had them, recorded in a new `ArgParen` tree flag, or where binding power requires them. A wrong tree's grouping then shows up as a paren the source lacks, by construction, with no forgiveness rule to leak through (A28, A29). This issue does the named unary ops, which perigrin measured (docs/measurements/2026-10-23-precedence-aware-canon/README.md, on branch feat/m3-oracle-at-scale until it merges; scratch worktree at 054e75e6, judged by perl 5.44). The three issues that follow (the measurement plus `not`; list ops, calls and niladics with ArgParen; then the rule removal) extend it and remove the rule. They are separate for sizing (P29, round 8): the round-7 pushback found the Paren-once issue at its limit. The comparator issue (d519) lands before this one, so this issue's `emit` signature change rebases over d519's small ParenNode offset recording in canon.go, not the other way round (P30, H12, L13, M9).

**The measurement, which this issue reproduces.** Today canon writes every Call parenthesised: `defined $x || $y` as `defined($x) || $y`, `chdir 't' if -d 't'` as `chdir('t') if -d('t')`, `shift` as `shift()`. Each is faithful only through the `isName` call-paren rule, which also forgives a wrong tree's `defined($x || $y)`. With named unary ops written by precedence and the rule turned off for them:

**The design.**
- **Set.** The parser's own classification: `namedUnaryHere` (keywordShape against CORE.tpm's derived shapes, which respects features and `CORE::`), plus file tests from `lexer.IsFileTest`, plus (K13/M2, round 8) the two file-visible user cases the parser already reads as unary through `knowsShape`: a sub declared in the file with a unary prototype (`($)`, `(_)`, `(;$)`; measured at 054e75e6, `sub one($){1} one $x, 2;` parses as `,`(one($x), 2) and canon writes `one($x) , 2`) and a `builtin::` unary import (`use builtin qw(blessed); blessed $o, 1;` parses the same way). The tree records all of it as `NamedUnary` on the Call node. 84 builtins at 054e75e6 (abs alarm caller chdir chomp chop chr chroot close closedir cos dbmclose defined delete do each eof eval evalbytes exists exit exp fc fileno getc getgrgid getgrnam gethostbyname getnetbyname getpeername getpgrp getprotobyname getpwnam getpwuid getsockname gmtime goto hex int keys lc lcfirst length localtime lock log lstat oct ord pop pos prototype quotemeta rand readdir readline readlink readpipe ref reset rewinddir rmdir scalar sethostent setnetent setprotoent setservent shift sin sleep sqrt srand stat study tell telldir tied uc ucfirst umask undef untie values write) plus the file tests.
- **Source parens.** `ArgParen` is set on a Call whose source wrote `NAME(`, the FUNC1 form. It is not `Paren`: `Paren` is the node's own grouping, `ArgParen` its argument list's.
- **Power.** `bpNamedUnary` (160 at 054e75e6, derived from CORE.tpm by `derivePowers`; `<` is 140, `eq` 130, `<<` 170, `+` and `.` 180, `*` 190, `||` 90, `or` 10, prefix `not` 30, `bpListOp` 40). A named unary without `ArgParen` is written `NAME OPERAND`, the operand emitted at `bpNamedUnary+1`, so a looser operand is wrapped: a wrong tree with `defined` over `||` writes `defined ($x || $y)`, which the source lacks. With no operand it writes the bare name (`shift`, `-e`).
- **The follow power.** A prefix op's parens depend on what FOLLOWS it, which `emit`'s `outer` does not carry: at a right-operand position, `!defined $x` and `$a . lc $b` must stay bare. So `emit` carries the binding power of the operator written right after the node (0 when a closer or nothing follows). A named unary falls back to call parens only when that power is tighter than `bpNamedUnary`: `defined($x) ** 2`. Binary: the left operand gets the operator's power, the right inherits. Ternary: the first two parts get `?`, the last inherits. CmpChain: each link gets the operator, the last inherits. Unary operands, declaration initialisers, LoopControl expressions and modifier conditions inherit. Postfix gets its own operator; Index children get `atomBP`; every other context gets 0; a node wrapped in parens resets it to 0.
- **Not covered here.** `not` (a prefix Unary, NOTOP, not a Call), list operators, calls and niladic builtins: the next three issues. `require` has its own canon path; `goto` goes through control.go; the `eval`/`do` BLOCK forms are skipped by design. A user sub with a `($)` prototype the file cannot see is parsed as a list op and written by the list-op issue; that is M4 prototype territory, and TestCanonWritesNamedUnaryByPrecedence's comment says so (round-7 ruling).
- **Faithful is not touched.** The call-paren rule stays in force until the rule-removal issue takes it out, so no file can drop here; the ratchets are the proof, and they fail in both directions. **So no test in this issue asserts "unfaithful" (M1, round 8):** while the rule exists, `defined ($x || $y)` from a wrong tree is still forgiven against `defined $x || $y` (fresh7 measured it true). The wrong-tree tests here assert canon's TEXT only; the unfaithful half is asserted by the rule-removal issue and by 75d4's extent negatives. "Emits exactly" means the significant tokens of canon's output (through `significantTokens`, the comparison Faithful makes) equal the expected string's, not the raw bytes: canon writes ` , ` between arguments (`push(@a , 1)` today), and the tests must not pin that spacing (fresh7's note, round 8).
- **A bare operand that starts with `(` (M4, round 8).** perl reads `NAME (` as call parens, so a wrong tree whose operand's emission begins with a `(` that does not enclose the whole operand would re-emit the source's tokens exactly: source `defined ($x) . "a"` (perl: `(defined($x) . 'a')`) with the wrong tree `defined` over `($x) . "a"` would emit `defined ($x) . "a"`. Canon therefore writes the call parens whenever the operand's emission begins with `(` and that pair does not close at the operand's end: that wrong tree emits `defined(($x) . "a")`, a paren the source lacks.

**The 11 tests that pin the old spelling** (`length("x")`, `-e($f)`, `keys(%h)`, `defined($a) , $b`, `-e()` for an operand-less file test, and so on), updated to the precedence spelling, each with the perl 5.44 evidence that the bare spelling re-parses to the same tree: TestBarewordFilehandleCase (barehandle_test.go), TestCoreUnaryAndListOperatorParseDiffer (corenoproto_test.go), TestCorePrefixedKeyword (coreprefix_test.go), TestCoreFeatureGatedBuiltinTypedParseUnchanged (coretypes_test.go), TestEmptyCommaSlot (emptycomma_test.go), TestFeatureGatedFcArity (featuregated_test.go), TestMainStashEmptyName (mainstash_test.go), TestOperandlessFiletest (operandless_test.go), TestParenlessBuiltinArity (parenlessarity_test.go), TestPrintScalarBeforeModifier (printmod_test.go), TestSortComparator (sortcmp_test.go). TestOperandlessFiletest's "swallowed the terminator" check reads `-e or` as a defect; perl reads the bare spelling the same way, so that check changes, not the code.
